# EnglishBuddy — Спецификация для разработки (v1)

> Дата: 2026-06-21. Автор интервью: Claude (discovery-interview).
> Тип: full-stack web-app. Стек: Next.js 16 (App Router) + React 19 + Tailwind v4 + Supabase + Anthropic SDK + ElevenLabs.
> Подход: **расширяем существующий каркас EnglishBuddy**, чиним критические дыры, достраиваем обучающее ядро.
> Реализовывать спецификацию будет Claude Code.

---

## 1. Executive Summary

EnglishBuddy — ИИ-репетитор английского языка для **B2C-самообучения**, который ведёт живой диалоговый урок и реально *учит языку*, а не просто общается. Ключевое отличие от «ещё одного чата с ИИ»: **зашитая методика преподавания** (коммуникативный подход + элицитация ошибок), **привязка к CEFR с измеримым прогрессом**, **интервальные повторения (SRS)** выученного и **структурированный силлабус**. Продукт строится для основателя (первый пользователь: уровень A1–A2, цель — работа + переезд + разговорный английский) с прицелом на монетизацию подпиской (инфраструктура заложена в модель данных, оплата — в P1).

«Обученность» репетитора реализуется **методикой в промптах** (без fine-tuning модели): система системных промптов + детерминированная логика + структурированный вывод через tool use.

---

## 2. Problem Statement

Существующий прототип EnglishBuddy функционально цельный (онбординг → урок-диалог → память ошибок → озвучка), но **архитектурно это умный ролевой чат-бот, а не обучающая система**. Подтверждено аудитом кода:

- Нет привязки к уровню (CEFR) и измеримого прогресса — `level_description` это свободный текст.
- Нет интервальных повторений — выученное не закрепляется и забывается.
- Нет силлабуса — темы выбираются случайно, причём механизм «не повторять темы» **сломан** (`scenario_title` нигде не записывается).
- Выученные ключевые фразы (`keyPhrases`) **нигде не сохраняются** — обучение не накапливается.
- Модель коррекции ошибок («сразу мягко исправить и ехать дальше») методически слабая для усвоения.
- Технические дыры безопасности: `/api/chat` и `/api/tts` **без авторизации**, системный промпт принимается **от клиента** (открытый прокси к платному ключу).

«Самый лучший репетитор» требует закрыть эти дыры и заложить доказательные механизмы усвоения второго языка.

## 3. Success Criteria

**Продуктовые (измеримые):**
- Пользователь видит свой CEFR-уровень и его рост во времени.
- ≥ 80% выученных ключевых фраз попадают в SRS и предъявляются к повторению по расписанию.
- Урок всегда начинается с релевантного повторения (review) ранее пройденного, если есть due-элементы.
- Темы уроков **не повторяются** (силлабус + корректно записанный `scenario_title`).
- Streak и дневная цель отображаются и обновляются корректно.

**Технические (acceptance-gate перед сервером):**
- Все API-роуты требуют авторизованную сессию; системные промпты собираются **только на сервере**.
- Никакие секреты не попадают в git; `npm run build` и `npm run lint` проходят чисто.
- Структурированный вывод модели (фаза урока, итоги, оценка уровня) работает через tool use, без парсинга маркеров регулярками.

**Метрика «учит ли он» (для себя как первого пользователя):**
- Через 2–3 недели ежедневных микро-уроков основатель субъективно отмечает рост уверенности в типовых рабочих/бытовых сценариях, а система показывает рост словаря и движение по CEFR-дескрипторам.

## 4. User Personas

**P1 — Основатель (первый пользователь, primary).**
Уровень A1–A2. Понимает простые фразы, говорить тяжело. Родной язык — русский. Ближайшая цель — английский для работы; среднесрочно — переезд, нужен разговорный/бытовой английский. Нужно много русского в объяснениях, низкий стресс, ощущение «я реально продвигаюсь».

**P2 — Будущий подписчик (B2C, secondary).**
Взрослый самоучка-русскоговорящий, учится сам, нерегулярно, легко бросает. Чувствителен к удержанию (streak, прогресс, напоминания). Платит за ощущение результата и за «настоящего» репетитора, а не флеш-карточки. **Уровень заранее неизвестен и НЕ выбирается пользователем вручную — его определяет сам ИИ-репетитор через входную диагностику, по всему диапазону CEFR (A1–C2).** У разных подписчиков он будет разным: у кого-то A2, у кого-то B2 или C1.

> Справка по CEFR (чтобы не путаться в названиях): уровни идут **A1 → A2 → B1 → B2 → C1 → C2** — от начинающего к уровню носителя. Промежуточного «B3» в шкале нет; следующий уровень после B2 — это C1.

## 5. Pedagogical Specification («обучение стилю» — ядро продукта)

Это центральный раздел: именно он делает репетитора «обученным». Реализуется в `lib/prompts/*` и в логике сборки промптов.

### 5.1. Персона репетитора
- Тёплый, терпеливый, неформальный, на «ты», объясняет на русском.
- Эмоциональная позиция: **здесь можно ошибаться, никто не осуждает**.
- Никогда не использует слова «неправильно/ошибка/плохо» → «почти», «ещё вариант», «по-английски чаще говорят так».
- Подбадривает практичностью («это тебе пригодится, когда…»), без приторности.

### 5.2. Методический подход — коммуникативный (communicative)
- **Максимум живой практики речи**, минимум сухой теории. Грамматика подаётся через ситуации, а не как набор правил.
- **Comprehensible input i+1:** репетитор даёт язык чуть выше текущего уровня ученика, оставаясь понятным.
- **Recycling:** ранее выученное намеренно вплетается в новые уроки (поддерживается SRS).
- **CEFR-скаффолдинг:** сложность речи репетитора и ожидания к ответам ученика привязаны к его CEFR-уровню.

### 5.3. Протокол коррекции ошибок — элицитация (выбрано пользователем)
При неточности в речи ученика репетитор:
1. **Сигнализирует** мягко, не давая сразу правильный ответ («почти! как думаешь, как сказать "…" правильно?» / переспрашивает с интонацией сомнения).
2. **Даёт ученику шанс самому переформулировать.**
3. Если ученик не справился со второй попытки — **тогда** даёт правильный вариант (recast) и просит повторить.
4. Не прерывает поток резко, без оценок и баллов.
> Это доказательно эффективнее для усвоения, чем немедленный recast. Заложить именно эту последовательность в промпт урока.

### 5.4. Соотношение L1/L2 (русский/английский) по уровню
- **A1–A2:** объяснения преимущественно на русском; английский — в целевых фразах и простой практике.
- **B1–B2:** объяснения смешанные, практика преимущественно на английском.
- **C1+:** почти всё на английском, русский — только для тонких нюансов.
Репетитор получает это правило в системном промпте вместе с текущим CEFR-уровнем.

### 5.5. Структура урока (4 фазы в одной непрерывной беседе)
1. **Review (SRS-повторение)** — если есть due-элементы (фразы/ошибки), урок начинается с быстрого тёплого повторения 2–4 из них в контексте. Если due нет — пропускается.
2. **Presentation (тема + объяснение)** — выбор сценария из силлабуса (релевантно цели и уровню, без повтора пройденного), краткое объяснение нужных слов/конструкций.
3. **Communicative practice (ролевой диалог)** — репетитор играет роль (секретарь, врач, HR, коллега), ученик отвечает на английском; коррекция по протоколу 5.3.
4. **Wrap-up (итог)** — 3–5 ключевых фраз + тёплое резюме; извлечение данных для сохранения (см. 7.4).

### 5.6. Диагностика уровня (placement) — определяет САМ ИИ-репетитор
- Уровень **не выбирается пользователем вручную** и не спрашивается «в лоб». Его определяет репетитор через короткую **адаптивную диалоговую диагностику** на онбординге (5–8 обменов).
- **Адаптивность:** репетитор начинает с простых задач и постепенно повышает сложность, пока ответы не начнут «ломаться» — так находится граница уровня. Оценивает по тому, КАК человек пишет/отвечает (словарь, грамматика, беглость, уверенность, понимание), а не по самооценке.
- **Полный диапазон CEFR:** результат — любой из **A1, A2, B1, B2, C1, C2** (не ограничен снизу/сверху). Сохраняется в `profiles.cefr_level` + `cefr_confidence` (low/medium/high).
- **Без экзаменационного стресса:** это тёплый разговор, а не тест с баллами; пользователь не должен чувствовать, что его «экзаменуют». (Опционально 2–3 калиброванных пункта внутри беседы — решается в Open Question 5.)
- **Переоценка во времени:** уровень не статичен. Каждые N завершённых уроков (или по накопленным сигналам) репетитор переоценивает уровень и может предложить повышение («ты вырос до B1») — это часть ощущения прогресса. Изменение фиксируется в истории прогресса.

## 6. User Journey

1. **Регистрация** → Supabase Auth (email/password). Триггер создаёт `profiles`.
2. **Онбординг** = диалоговая диагностика (5.6) + сбор цели (работа/переезд/разговорный). На выходе заполнены `goal`, `cefr_level`, `cefr_confidence`, `level_description`.
3. **Dashboard** — приветствие, текущий CEFR + прогресс-бар, streak/дневная цель, кнопка «Начать урок», количество due-повторений, история уроков.
4. **Урок** `/lesson/[id]` — 4 фазы (5.5), стриминг ответов, бейдж фазы, голос (TTS-озвучка + STT-ввод).
5. **Завершение урока** — экран с ключевыми фразами; в БД сохраняются: статус, `scenario_title`, новые `vocabulary_items`, обновления `error_memory`, SRS-расписание, streak, прогресс.
6. **Повторный заход** — следующий урок начинается с review due-элементов; темы не повторяются; сложность подстроена под уровень.
7. **Напоминания** — email-напоминание вернуться (привязано к streak/наличию due-повторений).
8. **Settings** — имя, цель, дневная цель, голос вкл/выкл, выход.

**Core action:** пройти диалоговый урок и закрепить выученное через повторения.

## 7. Functional Requirements

### P0 — Must Have (v1, без этого нельзя)

**Безопасность и корректность (чиним дыры):**
- **FR-01.** Все API-роуты (`/api/chat`, `/api/tts`, `/api/lesson/*`) проверяют сессию через `supabase.auth.getUser()`; неавторизованный запрос → 401.
- **FR-02.** Системный промпт собирается **на сервере** из профиля/памяти/силлабуса. Клиент НЕ передаёт `system`. `/api/chat` принимает только `{ sessionId, userMessage }` (или индекс хода), сервер сам подтягивает историю и пересобирает промпт.
- **FR-03.** `scenario_title` записывается при завершении урока (из структурированного вывода модели). Список пройденных тем реально наполняется.
- **FR-04.** Выученные ключевые фразы сохраняются в таблицу `vocabulary_items` (см. 8). Acceptance: после урока в БД появляются фразы с переводом и контекстом.
- **FR-05.** Структурированный вывод модели реализован через **Anthropic tool use** (а не текстовые маркеры `PHASE:`/`LESSON_COMPLETE:`). Сохранить ручную кнопку «Завершить урок» как safety-net.
- **FR-06.** `max_tokens` поднят до адекватного для урока (напр. 2048+); протестировано на длинных диалогах без обрыва.

**Обучающее ядро:**
- **FR-10.** CEFR-уровень определяется **самим ИИ-репетитором** через адаптивную входную диагностику (5.6), по полному диапазону A1–C2 (без ручного выбора пользователем). Хранение `cefr_level`/`cefr_confidence`, отображение на dashboard, переоценка во времени с записью в историю прогресса.
- **FR-11.** Прогресс: визуальный прогресс-бар по CEFR, рост словаря («выучено N фраз»), счётчик пройденных уроков.
- **FR-12.** SRS: каждый `vocabulary_item` и `error_memory` имеет расписание повторов; due-элементы предъявляются в фазе Review. Алгоритм — Leitner-подобный (боксы с интервалами, напр. 1/3/7/16/35 дней; при успехе бокс растёт, при ошибке сбрасывается в 1).
- **FR-13.** Силлабус: структурированная прогрессия юнитов (тема + грамматический фокус + лексическая тема + сценарий), привязанная к CEFR и треку цели (work / relocation-conversational). Репетитор выбирает следующий незавершённый юнит. Реализация — в коде (`lib/syllabus/`), консультируется при сборке промпта урока.
- **FR-14.** Коррекция ошибок по протоколу элицитации (5.3) — зашита в промпт урока.

**Голос (важная часть v1):**
- **FR-20.** TTS-озвучка реплик репетитора (ElevenLabs с fallback на `speechSynthesis`).
- **FR-21.** STT-ввод речью (Web Speech API, `lang='en-US'`), graceful fallback: если не поддерживается — кнопка микрофона скрыта, ввод текстом.
- **FR-22.** Автоозвучка при `voice_enabled=true` + ручная кнопка «🔊» на каждой реплике.

**Удержание:**
- **FR-30.** Streak: счётчик дней подряд + дневная цель (по умолчанию 1 урок/день), отображение на dashboard.
- **FR-31.** Видимый прогресс (см. FR-11) как механика удержания.
- **FR-32.** Email-напоминания вернуться (привязка к streak / наличию due-повторений). Реализация: scheduled job (Vercel Cron / Supabase) + транзакционный email-провайдер.

**Монетизация (только модель данных):**
- **FR-40.** В схеме БД заложены поля плана/подписки/лимитов (`plan`, `subscription_status`, лимиты). Stripe/paywall в v1 НЕ реализуются, но включаются позже без миграции-ломки.

### P1 — Should Have (следующий этап)
- Stripe Checkout + webhooks, paywall, free-tier лимиты, управление подпиской в UI.
- Web push-уведомления (в дополнение к email).
- Переоценка CEFR с явным «ты вырос до B1».
- Расширение силлабуса (больше юнитов, больше треков целей).

### P2 — Nice to Have
- **Оценка произношения** (анализ фонем/ударений по речи, направление ELSA).
- Бейджи/достижения за вехи.
- Мини-квизы на активное припоминание вне урока.
- Listening-практика (градуированное аудирование).

## 8. Technical Architecture

### 8.1. Data Model (изменения к существующей схеме)

**`profiles`** (расширить):
```
+ cefr_level text            -- 'A1'..'C2', nullable до диагностики
+ cefr_confidence text       -- low|medium|high
+ native_language text default 'ru'
+ goal_track text            -- 'work' | 'relocation' | 'conversational' | 'general'
+ daily_goal int default 1
+ streak_count int default 0
+ longest_streak int default 0
+ last_active_date date
+ plan text default 'free'           -- монетизация (модель данных)
+ subscription_status text default 'none'
+ subscription_period_end timestamptz
(существуют: user_id, display_name, goal, level_description, voice_enabled, created_at)
```

**`vocabulary_items`** (НОВАЯ — банк выученного + SRS):
```
id uuid pk, user_id uuid fk
phrase_en text not null
translation_ru text
context text                 -- пример употребления/сценарий
source_lesson_id uuid
srs_box int default 1        -- Leitner box
due_at timestamptz default now()
times_reviewed int default 0
last_reviewed_at timestamptz
created_at timestamptz default now()
```

**`error_memory`** (расширить SRS-полями, чтобы ошибки тоже повторялись):
```
+ srs_box int default 1
+ due_at timestamptz default now()
(существуют: id, user_id, description, topic, times_seen, last_reviewed_at, created_at)
```

**`lesson_sessions`** (использовать существующие + гарантировать запись):
```
scenario_title text          -- ОБЯЗАТЕЛЬНО заполнять при finish (FR-03)
+ syllabus_unit_id text       -- какой юнит силлабуса пройден
+ cefr_at_lesson text         -- срез уровня на момент урока
(существуют: id, user_id, messages jsonb, status, created_at, completed_at)
```

**Review-запрос:** due-элементы = `UNION` из `vocabulary_items` и `error_memory`, где `due_at <= now()`, отсортировано по `due_at`, лимит N (напр. 5).

RLS-политики — расширить на `vocabulary_items` по тому же паттерну (`auth.uid() = user_id`). Триггер автосоздания профиля — сохранить.

### 8.2. System Components
- **`app/api/chat/route.ts`** — стриминг-прокси к Claude. После рефактора: проверяет auth, по `sessionId` грузит историю + профиль + память + силлабус, сам собирает system-промпт, стримит ответ. Tool use для структурированного вывода (фаза, итоги).
- **`app/api/lesson/start|finish/route.ts`** — старт создаёт сессию; finish записывает `scenario_title`, `syllabus_unit_id`, апсертит `vocabulary_items` и `error_memory` с SRS, обновляет streak/прогресс.
- **`lib/prompts/`** — `persona.ts`, `lesson.ts`, `onboarding.ts` (диагностика), + новый слой методики (5.x).
- **`lib/syllabus/`** — структура юнитов + выбор следующего.
- **`lib/srs.ts`** — расчёт следующего `due_at`/`srs_box` (Leitner).
- **`lib/speech/`** — TTS/STT хуки (существуют).
- **`app/dashboard`** — прогресс, streak, due-счётчик, история.
- **Reminders job** — Vercel Cron → выборка пользователей с due/риском потери streak → email.

### 8.3. Integrations
- **Anthropic** (`@anthropic-ai/sdk`), модель `claude-sonnet-4-6` (качество диалога-репетитора приоритетно). Tool use для структурированного вывода. Ключ — только на сервере.
- **ElevenLabs** TTS (fallback `speechSynthesis`); лимит free-tier — продуктовый риск, обрабатывать gracefully.
- **Web Speech API** STT (Chrome/Edge надёжно; Firefox/Safari — fallback на текст).
- **Email-провайдер** (Resend/Supabase) для напоминаний.
- **Supabase** — Auth, Postgres, RLS.

### 8.4. Security Model
- Supabase Auth + middleware refresh сессии (существует).
- RLS на всех таблицах с пользовательскими данными.
- Все API-роуты — auth-gated; системные промпты и ключи только на сервере.

## 9. Non-Functional Requirements
