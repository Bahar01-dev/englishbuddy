# Roadmap — техдолг и улучшения

Отложенные находки код-ревью (2026-07-07). Срочные пункты (п.1–4) уже исправлены,
здесь — то, что решили сделать позже. Приоритет внутри секций сверху вниз.

## Можно позже

### 1. Per-user часовой пояс для напоминаний и dashboard
Сейчас граница «дня» для streak при завершении урока считается по поясу устройства
(клиент шлёт `tzOffsetMinutes`) — это корректно. Но cron-напоминания
([`app/api/cron/reminders`](app/api/cron/reminders/route.ts)) и server-компонент
[`dashboard`](app/dashboard/page.tsx) клиента не видят и используют домашний UTC+5
(`DEFAULT_TZ_OFFSET_MINUTES` в [`lib/streak.ts`](lib/streak.ts)). Для multi-user это
даст неточный выбор адресатов и «цель на сегодня» на границе суток.
**Фикс:** хранить пояс в `profiles` (колонка `tz_offset_minutes` или IANA-таймзона),
писать его на клиенте (онбординг/settings), читать в cron и dashboard.
**Зачем:** точные напоминания и отметка цели для пользователей вне UTC+5.

### 2. `lesson/finish` — батчинг записей (N+1)
[`app/api/lesson/finish/route.ts`](app/api/lesson/finish/route.ts): обновление ошибок
и продвижение vocab/errors по SRS идёт по одному `await` в цикле — до ~1+5+5
последовательных round-trip к БД на завершение.
**Фикс:** батч-`upsert`/`update ... in (...)` или `Promise.all` по независимым апдейтам.
**Зачем:** быстрее завершение урока, меньше нагрузка на БД.

### 3. Единый хук стриминга ассистента (дублирование)
[`app/lesson/[id]/page.tsx`](app/lesson/[id]/page.tsx) и
[`app/onboarding/page.tsx`](app/onboarding/page.tsx) содержат ~70 строк почти
идентичной логики (`sendToAssistant`, `failWith`, разбор потока, обработка
`extractStreamErrorKind`), которая уже начала расходиться.
**Фикс:** вынести в общий хук `useAssistantStream`.
**Зачем:** одна точка правды, меньше риска расхождения поведения.

### 4. `parseStream` не вырезает фрейм `[[AI_ERROR:...]]`
[`lib/stream-protocol.ts`](lib/stream-protocol.ts): `FRAME_RE` знает только
`PHASE|COMPLETE|DIAGNOSIS`. Маркер ошибки — валидно закрытый `[[...]]`, поэтому на
один кадр рендера может мелькнуть сырой `[[AI_ERROR:network]]` в пузыре до сброса.
**Фикс:** учесть `AI_ERROR` в вырезании (или общий парсер маркеров).
**Зачем:** косметика, убрать вспышку служебного текста.

### 5. Cron-напоминания: масштабирование
[`app/api/cron/reminders`](app/api/cron/reminders/route.ts): `select` по `profiles`
без фильтра тянет все профили; `listUsers({ perPage: 1000 })` жёстко обрезан на 1000
без пагинации → при росте потеря адресатов.
**Фикс:** пагинация `listUsers`, предфильтрация кандидатов на стороне БД.
**Зачем:** корректность при росте пользователей.

## Некритично

### 6. `runtime`/`maxDuration` не заданы в `lesson/start` и `lesson/finish`
В `chat`/`tts`/`cron` заданы, здесь — нет (полагаемся на дефолт Vercel).
**Фикс:** явно проставить `export const runtime = "nodejs"` для консистентности.

### 7. `classifyAiError`: любой `status >= 500` → `overloaded` (retryable)
[`lib/ai-errors.ts`](lib/ai-errors.ts): постоянная 500-ошибка конфига будет
бессмысленно ретраиться.
**Фикс:** различать 500 (не ретраить) и 502/503/529 (ретраить).

### 8. Магические пороги матчинга ошибок
[`lib/error-match.ts`](lib/error-match.ts): слова `length > 3`, `overlap > 0.4` — без
обоснования; на коротких описаниях возможны ложные совпадения/пропуски.
**Фикс:** подобрать и покрыть тестами граничные случаи после реальных данных.

### 9. Висячее user-сообщение после mid-stream ошибки
[`app/lesson/[id]/page.tsx`](app/lesson/[id]/page.tsx): user-ход персистится до
ответа; при ошибке ассистент не сохраняется, и при перезаходе урок показывает
вопрос без ответа и сам не продолжает.
**Фикс:** при возобновлении сессии, если последний ход — user, авто-дозапросить ответ
(или подсветить «Повторить»).

### 10. Наблюдаемость — только `console.*`
Для продакшена с оплатой стоит завести реальный сбор ошибок (Sentry и т.п.).
**Фикс:** интеграция error-tracking, чтобы `logAiError`/`console.warn` уходили в сервис.
